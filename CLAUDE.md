# CLAUDE.md — технический контекст проекта для AI-разработчика

Этот файл — для AI (Claude или любой другой кодинг-ассистент),
который будет вносить изменения в этот репозиторий. Прочитай его
перед любыми правками. Параллельно см. `HANDOFF.md` (вход для нового
разработчика «с нуля») и `docs/` (детальная документация по темам).

## 1. Архитектура — коротко

Чистый клиент-сайд проект, без своего backend-сервера:

```
Браузер покупателя          Браузер сотрудника
  index.html                   admin.html
  styles.css                   (свой inline <style>/<script>)
  app.js
       │                             │
       │   прямые REST-запросы       │
       └──────────┬──────────────────┘
                   ▼
        Supabase (Postgres + Auth + Storage)
        project: vjwnxbxtsglrvbxyhdza (eu-north-1, Stockholm)
                   ▲
                   │ раз в 5 минут читает и пишет
       GitHub Actions: sync-catalog.yml
                   │ коммитит
                   ▼
            lamps.json  (в этом же репо, отдаётся тем же
                          доменом, что и сайт — резервная
                          копия каталога на случай сбоя
                          прямого запроса к Supabase)
```

Deploy: push в `main` на GitHub → Timeweb App Platform автоматически
разворачивает статику (подключено через GitHub-интеграцию Timeweb).

Никакой сборки, транспиляции или bundling нет — что в репозитории,
то и грузится в браузер один в один.

## 2. Ключевые модули/файлы

| Файл | Роль |
|---|---|
| `index.html` | Разметка витрины — hero, бренды, каталог-сетка, «как купить», сотрудничество, контакты. Единая страница, собранная из нескольких смысловых блоков. |
| `app.js` | Вся клиентская логика витрины. Разбит на независимые IIFE-блоки по функциям (см. ниже). |
| `styles.css` | Все стили сайта и витрины, включая карточки, модалку, пагинацию, чипы фильтров. |
| `admin.html` | Полностью самодостаточная страница админки: HTML + CSS + JS в одном файле. Не переиспользует `app.js`/`styles.css`. |
| `lamps.json` | Автогенерируемая резервная копия каталога. **Не редактировать руками** — перезатирается ботом каждые 5 минут. |
| `.github/workflows/sync-catalog.yml` | Крон, который тянет каталог из Supabase REST API и коммитит `lamps.json`, если изменилось. |

### Структура `app.js` (IIFE-блоки сверху вниз)

1. Анимация золотого слогана в hero (`sloganWrap`, mousemove/raf).
2. Рендер списка брендов-партнёров (массив `BRANDS`, дублируется для
   бесконечной прокрутки-ленты).
3. **Главный блок — витрина каталога** (самый важный для бизнес-логики):
   - константы `SUPABASE_URL` / `SUPABASE_ANON_KEY` (публичный
     анонимный ключ, это ожидаемо и безопасно при включённом RLS);
   - `formatPrice(n)` — конвертация EUR→RUB по текущему `eurRate` и
     форматирование;
   - `discountPercent(l)` — расчёт процента скидки от `oldPrice`;
   - `renderCard`/`openModal` — рендер карточки и модалки;
   - фильтрация/поиск/пагинация (`getFiltered`, `render`,
     `renderPaged`, чипы типов, `discountSelect`, `pagerInput` —
     переход на конкретную страницу вводом номера);
   - `mapRows(rows)` — маппинг строк Supabase (`snake_case`,
     `old_price`) в модель UI (`camelCase`, `oldPrice`);
   - загрузка курса валюты: `fetchRate`, `readRateCache`/
     `writeRateCache` (`localStorage` ключ `podium_eur_rate_v1`);
   - загрузка каталога: `fetchWithTimeout` (AbortController) →
     `fetchLampsDirect` (запрос к Supabase, таймаут 6000ms) →
     при ошибке/таймауте **fallback** на `fetchLampsFallback()`
     (локальный `/lamps.json`) → `fetchLamps()` оборачивает оба;
   - кэш каталога в `localStorage` (`podium_lamps_cache_v1`,
     TTL ~5 минут) — чтобы при повторном заходе каталог показывался
     мгновенно, а свежие данные подтягивались в фоне.
4. Обработка `?sent=1` после отправки формы «Сотрудничество»
   (FormSubmit redirect-back).

### Структура `admin.html`

- Экран логина / основное приложение переключаются по наличию сессии
  Supabase Auth (`checkSession()` → `sb.auth.getSession()`).
- `sb` — Supabase-клиент (**не называть `supabase`** — см. раздел 5,
  «Что нельзя менять без проверки»).
- Таблица каталога: `loadLamps()` (`sb.from('lamps').select('*')`),
  поиск по таблице на клиенте (`renderTable`).
- Модалка добавления/редактирования светильника с полями `brand`,
  `article`, `type`, `name`, `price`, `old_price`, `dimensions`,
  `material`, `description`, `extra[]` (доп. характеристики), фото.
- Загрузка фото: `sb.storage.from('lamp-images').upload(...)` →
  `getPublicUrl(...)` → ссылка сохраняется в поле `image` записи.
- Панель курса валюты: `loadRate()` / `rateApplyBtn` click-handler —
  читает/пишет `public.settings` (`key = 'eur_rate'`).

## 3. Взаимосвязи между модулями

- `index.html`/`app.js` и `admin.html` **независимы друг от друга** —
  не импортируют общий код, у каждого свои копии
  `SUPABASE_URL`/`SUPABASE_ANON_KEY` и своя функция `esc()`
  (экранирование HTML). При смене Supabase-проекта или ключа нужно
  поправить **в обоих файлах**.
- Оба файла зависят от одной и той же схемы БД (`lamps`, `settings`)
  — поле добавленное/переименованное в одном месте должно быть
  согласовано в: схеме Supabase → `admin.html` (форма + таблица) →
  `app.js` (`mapRows`, рендер карточки/модалки) → `sync-catalog.yml`
  (если влияет на `lamps.json`, он просто зеркалит `select=*`, так
  что новые поля подхватятся автоматически).
- `lamps.json` — производная сущность, **источник истины всегда
  Supabase**, не наоборот. Ручное редактирование `lamps.json` имеет
  смысл только как временный хотфикс и будет перезатёрто ботом в
  течение 5 минут.
- `styles.css` используется только `index.html`. `admin.html`
  полностью самодостаточен по стилям.

## 4. Важные технические решения

- **EUR как единица истины**. Все цены в базе — в евро. Рубли
  вычисляются на лету на витрине (`price * eurRate`), не хранятся в
  БД. Это решение, чтобы при изменении курса не нужно было
  пересчитывать и перезаписывать 288 строк — достаточно поменять одно
  число в `settings`.
- **Публичный анонимный ключ Supabase в клиентском коде — это
  осознанно, не утечка**. Ключ ограничен Row Level Security: чтение
  `lamps`/`settings` разрешено всем, запись — только авторизованным.
  Не пытаться «спрятать» этот ключ в env на клиентском статическом
  сайте — это бессмысленно (он всё равно виден в devtools), важна
  именно настройка RLS в Supabase, а не секретность ключа.
- **Fallback-архитектура загрузки каталога** (прямой запрос →
  короткий таймаут → `lamps.json`) — осознанное решение под
  нестабильный доступ к зарубежным сервисам у части российских
  мобильных операторов. Таймаут 6000ms был увеличен с исходных
  2500ms, т.к. 2500 давал ложные срабатывания fallback на нормальном,
  но чуть медленном соединении.
- **`lamps.json` отдаётся с того же домена**, что и сайт
  (`podium-sale.ru/lamps.json`), не с Supabase — чтобы резервная
  копия не зависела от доступности того же внешнего хоста, который и
  мог отказать.
- **`old_price` заполняется только при наличии реальной
  подтверждённой референсной цены.** Никогда не придумывать/
  генерировать «старую цену» для создания видимости скидки — это
  нарушение ФЗ «О рекламе» (ст. 5, недостоверная реклама). Если
  источника нет — поле остаётся пустым, скидка на карточке просто не
  показывается.
- **Переменная Supabase-клиента в `admin.html` называется `sb`, а не
  `supabase`** — см. раздел 5.

## 5. Правила разработки / что нельзя менять без проверки

- **Никогда не объявлять в `admin.html` локальную переменную/константу
  с именем `supabase`.** UMD-скрипт `supabase-js` с `cdn.jsdelivr.net`
  уже создаёт глобальный `window.supabase`. Повторное объявление
  `const supabase = ...` в том же скоупе вызывает
  `SyntaxError: Identifier 'supabase' has already been declared`,
  которая **молча ломает вообще весь JS на странице**, включая кнопку
  входа — баг именно такого рода уже один раз полностью положил
  админку и был диагностирован не сразу, т.к. ошибка не всегда
  заметна без открытия консоли. Клиент называется `sb`.
- **Не трогать `.github/workflows/sync-catalog.yml` без понимания,
  что он коммитит в `main` от имени бота** (`catalog-sync-bot`) с
  правами `contents: write`. Он запускается каждые 5 минут — любая
  синтаксическая ошибка в нём тихо перестаёт обновлять
  `lamps.json`, а сайт заметит это только при сбое прямого запроса к
  Supabase.
- **Не редактировать `lamps.json` руками в репозитории** — это
  автогенерируемый файл, будет перезаписан при следующем срабатывании
  workflow. Любые правки каталога — только через `admin.html` (или
  напрямую в Supabase).
- **Не менять поля `price`/`old_price` на "рубли по умолчанию"** —
  вся архитектура (и `admin.html`, и `app.js`, и воркфлоу) построена
  на том, что в базе всегда евро. Смешение валют в одном поле без
  миграции всей схемы сломает и витрину, и админку одновременно.
- **При добавлении нового поля в `lamps`** — обновить одновременно:
  форму редактирования в `admin.html`, `renderTable()` в `admin.html`,
  `mapRows()` в `app.js`, и (если поле должно показываться
  покупателю) `renderCard`/`openModal` в `app.js`.
- **Таймауты `fetchWithTimeout`** (сейчас 6000ms и для каталога, и
  для курса) — не уменьшать бездумно, это уже один раз приводило к
  ложным "Каталог временно недоступен" на нормальном, но небыстром
  мобильном интернете.
- **Форма «Сотрудничество» отправляется через FormSubmit** — не
  переписывать на собственный backend без явного запроса, это рабочее
  текущее решение без поддержки своего сервера.
- Любое изменение, которое может сломать отображение цен или
  доступность каталога — **проверять вручную в браузере на живом
  продакшн-домене после деплоя** (специальных автотестов нет).

## 6. Где критическая бизнес-логика

- **Конвертация валюты и расчёт скидки** — `app.js`, функции
  `formatPrice()` и `discountPercent()`. Это самое чувствительное
  место: ошибка здесь напрямую показывает покупателю неверную цену.
- **Fallback-логика загрузки каталога** — `app.js`, блок
  `fetchWithTimeout`/`fetchLampsDirect`/`fetchLampsFallback`/
  `fetchLamps`. Отвечает за то, видит ли покупатель вообще каталог.
- **RLS-политики в Supabase** (не в репозитории, настраиваются в
  дашборде Supabase) — фактический источник того, кто что может
  читать/писать. Код в репо лишь использует эти правила, но не
  определяет их — см. `docs/database.md`.
- **Курс валюты** — `public.settings.eur_rate`, читается и `app.js`
  (витрина), и `admin.html` (панель управления). Единая точка истины
  для текущего курса.

## 7. Зависимости frontend/backend/database

- Frontend (`app.js`) напрямую зависит от схемы таблиц `lamps` и
  `settings` в Supabase — нет промежуточного API-слоя/контракта,
  любое изменение имени колонки в БД требует синхронного изменения
  кода.
- `admin.html` зависит от той же схемы плюс от Supabase Auth
  (конкретно — от наличия хотя бы одного пользователя в Auth с
  доступом на запись по RLS).
- `sync-catalog.yml` зависит от публичной доступности
  `GET /rest/v1/lamps` с анонимным ключом (чтение каталога не требует
  авторизации — специально, чтобы воркфлоу не нужен был отдельный
  сервисный токен).
- Продакшн-хостинг (Timeweb) зависит только от содержимого
  репозитория на `main` — никакой серверной конфигурации/переменных
  окружения на стороне Timeweb не задокументировано как
  используемое (сайт статический).

## 8. Важные UX/продуктовые решения, которые нельзя терять

- Покупатель **всегда** видит цены только в рублях — никогда не
  показывать на витрине евро (это сознательно упрощённое решение для
  целевой аудитории, принятое владелицей после первоначальной
  путаницы в постановке задачи).
- Сотрудник в админке **всегда** вводит/видит цены в евро — это
  стабильная «база», которая не должна дрейфовать при каждой смене
  курса.
- Смена курса в админке должна применяться на сайте **мгновенно, без
  редеплоя** — именно поэтому курс хранится в БД, а не захардкожен в
  `app.js`.
- Если `old_price` не подтверждён реальным источником — скидка на
  карточке просто не показывается, никогда не подставлять
  синтетическое значение (юридическое требование, см. раздел 4).
- Пагинация должна поддерживать как «вперёд/назад», так и прямой
  переход на номер страницы (была добавлена по явному запросу
  владелицы) — не упрощать обратно до только prev/next.
- Карточка при отсутствии фото должна показывать единообразную
  SVG-заглушку, а не сломанную картинку/пустоту.
