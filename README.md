# Podium Sale — распродажа шоурума «Подиум»

Сайт-витрина для акции «Распродажа шоурума» салона света и светотехники
«Подиум» (Санкт-Петербург). Публичный каталог последних экземпляров
светильников с ценами, фильтрами и быстрой заявкой менеджеру, плюс
отдельная админ-панель для сотрудников, где каталог и курс
евро→рубль редактируются без участия разработчика.

Продакшн: **https://podium-sale.ru**

---

## 1. Что это за проект и для чего он нужен

Шоурум «Подиум» распродаёт последние экземпляры европейских
светильников (Artemide, FLOS, Foscarini, Vibia и т.д.), закупленные
напрямую у фабрик без возможности повторной закупки. Сайт — отдельная
промо-страница (не основной сайт салона) с каталогом из ~288 позиций,
которую может полностью вести сотрудник без программиста:
добавлять/удалять светильники, менять цены, фото и курс валюты через
простую админку.

Ключевая идея устройства сайта: **цены в базе хранятся в евро**
(это «истина»), а на сайте для покупателя автоматически показываются
**в рублях** по курсу, который задаёт сотрудник в админке одной
кнопкой — без перезаливки сайта.

## 2. Текущий статус проекта

Проект в рабочем, активно используемом состоянии (production).

Реализовано и работает:
- публичный каталог светильников с фильтрами, поиском, пагинацией;
- админ-панель с логином, CRUD светильников, загрузкой фото, правкой
  курса валюты;
- автоматическая синхронизация резервной копии каталога
  (`lamps.json`) каждые 5 минут через GitHub Actions;
- отказоустойчивая загрузка каталога на сайте (прямой запрос к
  Supabase с коротким таймаутом → резервная копия `lamps.json` при
  сбое).

В работе / известные ограничения — см. раздел 15 и `HANDOFF.md`.

## 3. Стек технологий

- **Frontend**: чистый HTML/CSS/JS без сборщика и фреймворка
  (`index.html`, `styles.css`, `app.js` — ванильный JS, IIFE-модули).
- **Admin**: отдельная самодостаточная страница `admin.html` (HTML +
  inline `<style>`/`<script>`), использует
  [`@supabase/supabase-js` v2](https://www.npmjs.com/package/@supabase/supabase-js)
  (UMD-сборка с `cdn.jsdelivr.net`) напрямую в браузере.
- **Backend / БД**: [Supabase](https://supabase.com) (управляемый
  Postgres + Auth + Storage + авто-REST API через PostgREST). Нет
  отдельного серверного backend-кода — сайт обращается к Supabase
  REST API напрямую с клиента.
- **Хранилище файлов**: Supabase Storage, публичный bucket
  `lamp-images` — туда загружаются фото светильников из админки.
- **Авторизация**: Supabase Auth (email/password), один общий
  аккаунт сотрудника для входа в админку.
- **Хостинг / деплой**: Timeweb App Platform — автодеплой статики
  при каждом push в GitHub (~15–30 сек).
- **Автоматизация**: GitHub Actions
  (`.github/workflows/sync-catalog.yml`) — каждые 5 минут выгружает
  каталог из Supabase в `lamps.json` и коммитит, если есть изменения.
- **Форма «Сотрудничество»**: отправляется через сторонний сервис
  [FormSubmit](https://formsubmit.co) (без собственного бэкенда).

Зависимостей, которые нужно `npm install`, у проекта нет — это
статические файлы, подключающие единственную внешнюю библиотеку
(`supabase-js`) через `<script src="...">` прямо в `admin.html`.

## 5. Как запустить проект локально с нуля

Специального dev-сервера не требуется — это статические файлы.

```bash
git clone https://github.com/belykhveronika-netizen/podium-sale-site
cd podium-sale-site

# Любой простой статик-сервер, например:
python3 -m http.server 8080
# или
npx serve .
```

Откройте `http://localhost:8080/index.html` — витрина; каталог и курс
валюты подтянутся напрямую из Supabase (используется публичный
анонимный ключ, зашитый в `app.js`, см. раздел 9).

Админка: `http://localhost:8080/admin.html` — для входа нужен реальный
аккаунт Supabase Auth (см. раздел 10), секретов в коде для этого нет.

Никакой сборки (webpack/vite/npm run build) не требуется и не
предусмотрено.

## 6. Зависимости

Внешних npm-зависимостей и `package.json` в проекте нет. Единственная
внешняя библиотека — `@supabase/supabase-js@2`, подключается прямо в
`admin.html` через CDN:

```html
<script src="https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2/dist/umd/supabase.js"></script>
```

На публичной витрине (`index.html`/`app.js`) никаких библиотек нет —
только `fetch`/`AbortController` и ванильный DOM API.

## 7. Переменные окружения

Сайт полностью клиентский — "переменных окружения" в привычном
серверном смысле нет: URL и анонимный ключ Supabase зашиты прямо в
`app.js` и `admin.html` как константы (это нормально для Supabase —
анонимный ключ рассчитан на использование в браузере и ограничен
правилами доступа RLS на стороне базы).

Единственное место, где реально используются секреты в виде env —
GitHub Actions workflow `.github/workflows/sync-catalog.yml`. Сейчас
URL и анонимный ключ там тоже прописаны прямо в YAML (это тот же
публичный анонимный ключ, не секрет в строгом смысле). Список
переменных, которые имеет смысл учитывать при переносе/доработке
проекта, задокументирован в `.env.example` — используйте его как
шаблон, если будете переносить конфигурацию в секреты GitHub Actions
или заводить серверную часть.

## 9. База данных и её структура

Подробно — в `docs/database.md`. Кратко:

Supabase Postgres, проект `vjwnxbxtsglrvbxyhdza`, две таблицы:

- **`public.lamps`** — каталог светильников (~288 строк). Ключевые
  поля: `id, brand, article, type, name, price, old_price, dimensions,
  material, description, image, extra, sort_order, created_at`.
  `price`/`old_price` — **всегда в евро**, это постоянная база, не
  зависящая от курса. `image` — публичная ссылка на Supabase Storage.
- **`public.settings`** — key-value таблица для настроек сайта,
  сейчас одна строка `key = 'eur_rate'`, значение — текущий курс
  евро→рубль, который правится из админки и используется витриной для
  перевода цен в рубли на лету.

Доступ — через автогенерируемый Supabase REST API (PostgREST) прямо
из браузера, по анонимному ключу. Чтение каталога и курса публично
(RLS allow `select` для всех), запись разрешена только
авторизованным пользователям (роль `authenticated`).

## 10. Как работает авторизация

Supabase Auth, тип — email/password. Один общий аккаунт сотрудника
для входа в `admin.html` (учётные данные хранятся не в коде — см.
`HANDOFF.md`/передаются владельцу отдельно). Публичная витрина
(`index.html`) авторизации не требует — каталог читается анонимно.

Вход в админке: `sb.auth.signInWithPassword({ email, password })`.
Сессия хранится Supabase SDK в браузере автоматически; при открытии
`admin.html` сначала проверяется `sb.auth.getSession()` — если сессии
нет, показывается форма логина.

## 11. Как происходит деплой

1. Код редактируется и коммитится в GitHub-репозиторий
   `belykhveronika-netizen/podium-sale-site`, ветка `main`.
2. **Timeweb App Platform** подключён к этому репозиторию через
   GitHub-интеграцию и автоматически разворачивает статику при каждом
   push в `main` (занимает ~15–30 секунд).
3. Отдельно, раз в 5 минут, GitHub Actions
   (`sync-catalog.yml`) сам коммитит обновлённый `lamps.json` в
   `main` — это тоже триггерит автодеплой на Timeweb.

Никакого ручного шага «собрать и залить» нет — push в `main` это
единственное действие, нужное для деплоя.

## 13. Основные пользовательские сценарии

**Покупатель:**
1. Заходит на `podium-sale.ru`, видит шапку акции и бренды-партнёры.
2. Листает/фильтрует каталог светильников (чипы по типу, поиск,
   фильтр по проценту скидки, постраничная навигация с переходом на
   конкретную страницу).
3. Открывает карточку светильника — видит полные характеристики,
   цену в рублях, кнопку звонка менеджеру.
4. Либо звонит по телефону прямо с карточки, либо листает до блока
   «Сотрудничество» и оставляет заявку через форму.

**Сотрудник (админка):**
1. Заходит на `podium-sale.ru/admin.html`, логинится.
2. Видит таблицу всех светильников, может искать по названию/бренду/
   артикулу.
3. Добавляет/редактирует/удаляет позицию (цена указывается в евро),
   загружает фото.
4. При необходимости меняет курс евро→рубль в отдельной панели
   «Курс евро для сайта» и жмёт «Применить» — на сайте для
   покупателей автоматически обновляются рублёвые цены (без
   редеплоя).

## 14. Что уже реализовано

- Каталог ~288 светильников с ценами, фото (кроме 1–2 позиций),
  фильтрами по типу/скидке, поиском, пагинацией с переходом на
  произвольную страницу.
- Модальное окно карточки товара с полными характеристиками.
- Админ-панель: логин, CRUD каталога, загрузка фото в Supabase
  Storage, панель управления курсом валюты.
- EUR→RUB конвертация цен на лету на основе курса из `settings`, с
  кэшированием в `localStorage` на случай сетевых сбоев.
- Отказоустойчивая загрузка каталога (прямой Supabase-запрос с
  коротким таймаутом → fallback на `lamps.json` того же домена) —
  сделано специально под нестабильный доступ к зарубежным сервисам у
  части российских пользователей/операторов.
- Автосинхронизация `lamps.json` из Supabase каждые 5 минут через
  GitHub Actions (подтверждено рабочим — см. историю коммитов
  `Auto-sync catalog`).
- Форма «Сотрудничество» с отправкой на email через FormSubmit.

## 15. Что сейчас находится в работе / известные проблемы и ограничения

- **Фото**: у 1–2 позиций в каталоге может отсутствовать фото
  (отображается SVG-заглушка) — зависит от текущего состояния базы,
  проверять через админку.
- **Цены "было/стало"**: поле `old_price` заполнено не для всех
  позиций — осознанно, оно проставляется только там, где есть
  реальная подтверждённая референсная цена (во избежание нарушения
  ФЗ «О рекламе», ст. 5, о недостоверных «старых ценах»). Это
  осознанное бизнес-правило, не баг.
- **Неопределённость с Vercel**: в коде остался комментарий со
  ссылкой на Vercel-деплой админки — нужно уточнить у владельца,
  актуален ли этот адрес, или это след более ранней версии проекта
  (см. раздел 12 выше и `docs/deployment.md`).
- **Нет локальной валидации форм** в админке сверх базовой (например,
  не проверяется формат артикула) — полагается на дисциплину
  сотрудника.
- **Нет тестов** (unit/e2e) — проект изначально не предполагал
  тестового покрытия; изменения проверяются вручную в браузере.
- Полный список открытых вопросов и правил — в `HANDOFF.md` и
  `CLAUDE.md`.
