# HANDOFF.md — старт для нового AI-разработчика

Ты впервые открываешь этот репозиторий. Этот документ — твой
основной контекст, чтобы продолжить разработку без необходимости
заново разбираться во всём с нуля. Прочитай его целиком перед первой
правкой.

## Что это за продукт?

Сайт-распродажа последних экземпляров светильников салона света
«Подиум» (Санкт-Петербург): публичная витрина каталога
(`podium-sale.ru`) + отдельная админ-панель (`podium-sale.ru/admin.html`)
для нетехнического сотрудника, который сам ведёт каталог, цены и курс
валюты. Backend — Supabase (БД + авторизация + файлы), сайт —
статические HTML/CSS/JS без сборки, деплой автоматический через
Timeweb при push в GitHub.

Полное описание — `README.md`. Техническая архитектура — `CLAUDE.md`
и `docs/architecture.md`.

## В каком состоянии он сейчас?

Рабочий продакшн-проект, активно используется. На момент последнего
полного ревью (см. git-историю и дату этого коммита):
- каталог ~288 позиций, цены/скидки отображаются корректно;
- EUR→RUB конвертация работает через `public.settings.eur_rate`;
- резервная копия `lamps.json` **подтверждена рабочей** (регулярные
  автокоммиты `Auto-sync catalog` от GitHub Actions);
- админка работает (логин, CRUD, загрузка фото, панель курса).

Список открытых вопросов и ограничений — раздел «Какие задачи сейчас
актуальны» ниже и `README.md`, раздел 15.

## Как его запустить?

```bash
git clone https://github.com/belykhveronika-netizen/podium-sale-site
cd podium-sale-site
python3 -m http.server 8080
```

Открыть `http://localhost:8080/index.html` (витрина) или
`http://localhost:8080/admin.html` (админка, нужен реальный логин).
Сборки нет, npm-зависимостей нет. Подробнее — `docs/development.md`.

**Важно**: сайт обращается к боевому Supabase напрямую, отдельной
тестовой базы нет. Будь осторожен с записью данных через локально
открытую админку — это настоящий продакшн-каталог.

## Где искать основные части кода?

- `index.html` + `app.js` + `styles.css` — публичная витрина.
- `admin.html` — вся админка (самодостаточный файл).
- `lamps.json` — автогенерируемая резервная копия каталога,
  **не редактировать руками**.
- `.github/workflows/sync-catalog.yml` — крон синхронизации
  каталога с Supabase.

Подробная карта файлов и функций — `CLAUDE.md`, разделы 1–2.

## Как устроена архитектура?

Клиент-сайд приложение без собственного backend-сервера. И витрина,
и админка обращаются напрямую к Supabase REST API
(`vjwnxbxtsglrvbxyhdza.supabase.co`) с клиента, используя публичный
анонимный ключ (это безопасно и ожидаемо — границу доступа
обеспечивает Row Level Security в Supabase, не секретность ключа).
Диаграмму потоков данных см. `docs/architecture.md`.

## Какие решения уже приняты?

Ключевое — не пересматривать без явного запроса владелицы бизнеса:
- **Цены в БД — всегда в евро**; рубли для покупателя вычисляются на
  лету по курсу из `settings.eur_rate`. Покупатель никогда не видит
  евро, сотрудник в админке никогда не вводит рубли.
- **`old_price` заполняется только при наличии реального
  подтверждённого источника цены** — юридическое требование
  (ФЗ «О рекламе»), не технический выбор.
- **Fallback на `lamps.json`** при сбое прямого запроса к
  Supabase — часть продукта (нестабильный доступ к иностранным
  сервисам у части российской аудитории), не временный костыль.
- Переменная Supabase-клиента в `admin.html` называется **`sb`**, не
  `supabase` (см. ниже «что нельзя случайно сломать»).

Полный список и обоснования — `CLAUDE.md` (разделы 4, 8) и
`docs/product.md`.

## Что нельзя случайно сломать?

1. **Не объявлять в `admin.html` переменную/константу с именем
   `supabase`.** UMD-скрипт `supabase-js` уже создаёт глобальный
   `window.supabase`; повторное объявление даёт `SyntaxError`,
   которая **молча ломает весь JS страницы**, включая кнопку входа
   (это уже случалось и полностью положило админку до диагностики).
2. **Не редактировать `lamps.json` руками в репозитории** —
   перезатрётся ботом в течение 5 минут, это производный файл.
3. **Не менять модель хранения цен** на "рубли по умолчанию" — вся
   система (БД, админка, витрина, воркфлоу) построена на том, что
   в базе всегда евро.
4. **Не придумывать значения `old_price`** без реального источника —
   юридический риск, не просто стиль.
5. **Не укорачивать таймауты в `fetchWithTimeout`** бездумно — уже
   приводило к ложным "Каталог недоступен" на нормальном, но
   небыстром соединении (сейчас 6000ms, было 2500ms).
6. **Не трогать `.github/workflows/sync-catalog.yml`** без понимания,
   что он коммитит в `main` каждые 5 минут от имени бота с правами
   на запись — синтаксическая ошибка в нём тихо остановит обновление
   резервной копии.

## Какие задачи сейчас актуальны?

- Уточнить у владелицы, актуален ли Vercel-деплой админки, упомянутый
  в комментарии `app.js` (`podium-rasprodazha-...vercel.app`), или
  это след более ранней версии проекта — см.
  `docs/deployment.md`, раздел «Известные неясности». До выяснения
  **не менять DNS/хостинг**, опираясь только на это упоминание.
- Нет открытых недоделанных фич на момент этого handoff — проект в
  стабильном рабочем состоянии. Следующие задачи обычно приходят от
  владелицы бизнеса (новые позиции каталога, изменения в UX,
  изменения в правилах отображения цен).

## Какие известные проблемы есть?

- Комментарий в `app.js` может указывать на устаревший/альтернативный
  URL админки (Vercel) — см. выше.
- Публичный анонимный ключ Supabase прописан открытым текстом и в
  клиентском коде (`app.js`, `admin.html`), и в
  `.github/workflows/sync-catalog.yml`. Это ожидаемо и не является
  уязвимостью (ключ публичный по дизайну Supabase, защита — RLS), но
  как хорошая практика, значения в workflow стоило бы вынести в
  GitHub Secrets (не сделано намеренно в рамках этой задачи, чтобы не
  трогать рабочий код без необходимости).
- Нет автотестов — весь контроль качества ручной, в браузере.
- 1–2 позиции каталога на момент последней проверки могли быть без
  фото — не баг, а вопрос контента, решается через админку.

## Что нужно проверить перед внесением изменений?

1. Прочитать `CLAUDE.md` целиком (технические решения и правила).
2. Если меняется что-то про цены/валюту — прочитать `docs/product.md`
   (там обоснования бизнес-правил, которые нельзя терять).
3. Если меняется схема БД — прочитать `docs/database.md` и помнить
   про три места синхронизации (Supabase, `admin.html`, `app.js`).
4. Проверить актуальные номера версий `?v=N` у `styles.css`/`app.js`
   в `index.html` перед правкой этих файлов (см.
   `docs/development.md`).

## Как проверить, что изменения не сломали проект?

Полный чек-лист — `docs/development.md`, раздел «Как проверить, что
изменения не сломали проект». Коротко: открыть продакшн-сайт в
инкогнито, проверить консоль на ошибки, проверить каталог/фильтры/
пагинацию/модалку, зайти в админку и проверить логин + таблицу +
панель курса, при изменении данных — подождать до 5 минут и сверить
`lamps.json`.
