# Разработка

## Запуск локально

Проект — чистая статика, сборки нет.

```bash
git clone https://github.com/belykhveronika-netizen/podium-sale-site
cd podium-sale-site
python3 -m http.server 8080   # или: npx serve .
```

- Витрина: `http://localhost:8080/index.html`
- Админка: `http://localhost:8080/admin.html` (нужен реальный логин
  Supabase Auth — секретов в коде для входа нет)

Оба файла обращаются к **боевому** Supabase-проекту напрямую (своей
локальной/тестовой базы в проекте не предусмотрено) — будьте
аккуратны при тестировании записи данных через локально открытую
`admin.html`: изменения уйдут в реальный продакшн-каталог.

## Редактирование файлов

- `index.html` / `styles.css` / `app.js` — редактируются напрямую,
  никакой генерации/сборки не требуется.
- `admin.html` — полностью самодостаточный файл, стили и скрипт
  внутри него же.
- `lamps.json` — **не редактировать руками**, автогенерируется
  GitHub Actions каждые 5 минут из Supabase.

## Версионирование статики / кэш-бастинг

В `index.html` подключение стилей и скрипта идёт с query-параметром
версии:

```html
<link rel="stylesheet" href="styles.css?v=8">
...
<script src="app.js?v=6" defer></script>
```

При существенных изменениях `styles.css`/`app.js` стоит увеличивать
`?v=N`, чтобы у пользователей с агрессивным кэшированием браузера/CDN
гарантированно подтянулась новая версия файла. Проверяйте актуальные
номера прямо в `index.html` перед правкой — они могли измениться
после хотфиксов, сделанных напрямую через веб-редактор GitHub без
обновления этой документации.

## Процесс деплоя при разработке

1. Закоммитить и запушить изменения в `main` на GitHub.
2. Timeweb App Platform автоматически разворачивает статику
   (~15–30 секунд).
3. Проверить изменения на `https://podium-sale.ru` вручную в браузере
   — автотестов нет, весь контроль качества — ручная проверка в
   браузере (и, по возможности, инкогнито-режим/разные устройства,
   т.к. в прошлом были баги, воспроизводимые только со старым
   закэшированным JS на клиенте).

## Как проверить, что изменения не сломали проект

Чек-лист перед тем, как считать правку завершённой:

1. Открыть `podium-sale.ru` в браузере (лучше в режиме инкогнито,
   чтобы исключить кэш) — каталог должен загрузиться и показать
   позиции с ценами в рублях.
2. Открыть консоль разработчика (F12) — не должно быть ошибок
   (особенно `SyntaxError`, который в этом проекте уже один раз тихо
   ломал весь `admin.html` целиком — см. `CLAUDE.md`, раздел 5).
3. Проверить фильтры (чипы типов, поиск, фильтр по скидке) и
   пагинацию (включая прямой переход на страницу по номеру).
4. Открыть карточку товара (клик по карточке) — модалка должна
   показать характеристики и правильную цену.
5. Зайти в `podium-sale.ru/admin.html`, залогиниться, убедиться, что
   таблица каталога загружается и панель курса валюты показывает
   текущее значение.
6. Если менялось что-то в `lamps`/`settings` — проверить, что после
   следующего срабатывания `sync-catalog.yml` (до 5 минут) обновился
   и `podium-sale.ru/lamps.json`.
7. Проверить мобильную раскладку (сайт адаптивный, карточки должны
   вставать в одну колонку на узких экранах).

## Известные хрупкие места (проверять особенно внимательно)

- Переименование/удаление переменной `sb` в `admin.html`, или
  повторное объявление имени `supabase` в том же скоупе — ломает
  **весь** JS страницы молча, без видимой ошибки без открытия
  консоли.
- Изменение таймаутов в `fetchWithTimeout` — слишком короткий таймаут
  даёт ложный fallback/ошибку на нормальном, но небыстром соединении.
- Любое изменение имён колонок в Supabase без синхронного обновления
  `mapRows()`/форм в `admin.html`.

## Стиль кода

Ванильный JS, без TypeScript, без линтера/форматтера в репозитории.
Комментарии в коде — на русском, объясняют "зачем", а не "что"
(стоит придерживаться этого же стиля при дальнейшей разработке, т.к.
основной человек, сопровождающий контент сайта — не разработчик).
